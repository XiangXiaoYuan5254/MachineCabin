本地优先

数据留在本机，
哪儿也不去。

机舱不需要账号，不连接任何云端服务。它只和你的开发机打交道。

  • 只监听 127.0.0.1

    控制台默认只在本机回环地址上提供服务，不会暴露给局域网。

  • 配置保存在本地

    服务列表和运行日志都存放在本机：macOS 在 ~/Library/Application Support/机舱，Windows 在 %APPDATA%\机舱。

  • 删除只删记录

    从机舱中删除服务，只会移除这条记录，不会碰你的项目文件。

macOS 系统要求

  • macOS 13 Ventura 或更高版本
  • Apple Silicon 芯片（M 系列）
  • 已安装 Node.js 18 或更高版本

macOS 安装步骤

  1. 打开 DMG，把「机舱」拖进「应用程序」文件夹。
  2. 机舱目前还没有经过 Apple 公证。第一次打开如果被系统拦下，请到「系统设置 → 隐私与安全性」，点击「仍要打开」。
  3. 如果提示“已损坏，无法打开”，在终端执行下面这行命令后再打开：
    xattr -dr com.apple.quarantine /Applications/机舱.app

Windows 系统要求

  • Windows 10 或 Windows 11
  • 64 位（x64）处理器
  • 已内置运行环境，无需安装 Node.js

Windows 安装步骤

  1. 运行下载好的安装程序，按提示完成安装。默认安装在当前用户下，不需要管理员权限。
  2. 机舱目前还没有代码签名。如果 Windows 提示“已保护你的电脑”，点击「更多信息」，再点击「仍要运行」。
  3. 从开始菜单或桌面打开「机舱」。关闭窗口后，由机舱启动的服务会继续在后台运行，下次打开时会自动识别。

常见问题

你可能想知道

没找到答案？欢迎到 GitHub Issues 提问。

机舱会上传我的数据吗？

不会。控制台只监听 127.0.0.1，服务配置和运行日志都保存在本机，机舱不需要账号，也不连接任何云端服务。

为什么 macOS 版需要安装 Node.js？

机舱内置的控制台服务基于 Node.js 运行。Windows 版已经自带运行环境，不需要另外安装；macOS 版则会依次在 /opt/homebrew/bin、/usr/local/bin、/usr/bin 中查找 node，找不到时会提示你先安装。用 Homebrew 安装最方便：brew install node。

支持 Intel 芯片的 Mac 吗？

目前发布的安装包是 Apple Silicon 版本。Intel Mac 可以从 GitHub 获取源码，运行 ./script/build_and_run.sh --install 自行构建安装。

能停止不是机舱启动的进程吗？

可以，但有限制：只有当进程的工作目录位于该服务的项目目录内时才允许停止（Windows 上读不到其他进程的工作目录，改为检查进程的命令行是否指向项目目录）。这样可以避免误杀恰好占用同一端口的其他程序。

删除服务会删除我的项目吗？

不会。删除只会移除机舱中的那条记录，项目目录和文件都原样保留。

不想装 App，可以直接在浏览器里用吗？

可以。克隆源码后依次运行 npm install、npm run build、npm start，然后访问 http://127.0.0.1:49152。在 App 里也可以按 ⇧⌘O 用浏览器打开控制台。

配置文件保存在哪里？

macOS 版的数据保存在 ~/Library/Application Support/机舱/services.json，卸载时把「应用程序」里的机舱和这个目录一起删除即可。Windows 版保存在 %APPDATA%\机舱\services.json，在「设置 → 应用」中卸载机舱后，可以再手动删除这个目录。
